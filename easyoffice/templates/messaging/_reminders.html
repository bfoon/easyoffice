{% comment %} templates/messaging/_reminders.html ─────────────────────────────────── ⏰ The reminder popup, its poller, and the "remind me" composer. Include this ONCE from base.html, inside the authenticated shell, near the closing : {% if request.user.is_authenticated %}{% include "messaging/_reminders.html" %}{% endif %} It is a separate include rather than part of chat_room.html because a reminder must reach you wherever you are. Sitting on the leave-request page at 09:00 is exactly when the 09:00 reminder needs to appear, and a popup that only exists inside the chat room would miss it. Delivery is two paths on purpose: • the WebSocket push (instant, but only when a chat socket is open) • a poll of /messages/reminders/open/ (the guarantee) The poll is what makes a reminder impossible to miss — "open" is a state in the database, not an event, so one that fired while the laptop was shut is still waiting on the next request. The socket only saves you the wait for the next tick. {% endcomment %}
